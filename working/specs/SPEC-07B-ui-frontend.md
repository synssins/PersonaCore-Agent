# SPEC-07B — UI frontend: WebView2 window + systray + toast notifications

**Executor tier:** sonnet. **Branch:** `feat/spec-07b-ui-frontend`. **Worktree:** `../wsa-spec-07b/`.
**Depends on:** SPEC-01, SPEC-07A (backend), SPEC-06 (update flow surface).

## Goal

The visible desktop surface: WebView2 window pointed at the local FastAPI (SPEC-07A), pystray icon with full right-click menu, Windows toast notifications with action buttons.

## Critical architectural constraint (from plan audit)

**`pywebview` requires the main thread on Windows.** The composition root (SPEC-10) will:
- Run `pywebview.start()` on the main thread.
- Run the asyncio event loop on a background thread.

This SPEC delivers:
- A `WebviewWindow` class whose `start()` is a **blocking call intended for the main thread**.
- A `SystemTray` class whose `run()` also runs on the main thread — but pystray + pywebview + Windows event loops must coexist. Coordinate via pywebview's own timer + pystray's dedicated thread (`pystray.Icon(...).run_detached()`). Document this coordination explicitly in module docstrings.

## Files to create / modify (only these)

- `src/workstation_agent/ui/webview/window.py`:
  - `class WebviewWindow`:
    - `configure(url_provider: Callable[[], str])` — url_provider returns `http://127.0.0.1:<port>{path}` (port read from SPEC-07A's `ui-port` file).
    - `open(path: str)` — thread-safe request to show/navigate the window. If window not yet created, create it (deferred to next main-thread tick).
